# Clean single-fold detector and conditioned crop refiner

Status: specification only, September 6, 2026. This document does not launch training. The current full-train/submission takes priority on the P100.

**Question:** does instance-level context plus native-image refinement recover large/long filaments and reject unsupported small detections more effectively than the frozen precision-v2 development checkpoint? The measured motivation is in [the generalization audit](generalization_gap_analysis.md): 85/148 large truths are missed and 528/801 false predictions are tiny.

## Comparison contract

Use the preserved [manifest](../splits/split_manifest.csv): 495 train JPEGs, 106 validation JPEGs, all their independent annotation records. All filament categories form one foreground class. Sample a complete annotation set per JPEG presentation; do not concatenate disagreeing annotators as duplicate instances. The 106 internal-test images and 180 competition images never provide training targets or model-selection scores. No undocumented public MAGFiLO checkpoints. Hash original generic weights, train membership, installed packages, source, and outputs. Compare against the existing train-only precision-v2 model; its subsequent full-train descendant is ineligible for this validation comparison.

## Stage A: proposal and coarse mask baseline

Use torchvision **Mask R-CNN ResNet50-FPN, COCO_V1** as the first controlled instance model. Its public interface supplies boxes, scores, and soft instance masks, providing an independently useful detector baseline before adding a refiner. Start from its generic COCO checkpoint and replace box/mask output heads for background plus filament, as in the official fine-tuning tutorial. This is an engineering choice for a clear coarse-mask/refined-mask ablation, not evidence that Mask R-CNN is the best possible architecture. Sources: [official model and weights](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.detection.maskrcnn_resnet50_fpn.html), [official fine-tuning tutorial](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial.html).

Input: grayscale repeated across three channels, range [0,1], model's documented normalization applied exactly once. Begin with 1,024-pixel full-frame detector input and batch one, FP32, gradient accumulation four. Enable larger batch or mixed precision only after a timed P100 optimizer-step smoke test confirms finite losses and actual benefit. Record GPU architecture support, torchvision compiled NMS/ROIAlign availability, package versions, peak device allocation, and seconds/step; do not assume a newer CUDA wheel supports Pascal. Sequential detector/refiner jobs avoid simultaneous GPU residency.

Use the already verified compatible starting pair **PyTorch 2.7.1+cu126 / torchvision 0.22.1+cu126**. Its `sm_60` matrix smoke test passed in the prior Kaggle P100 audit; installation took 224 seconds. Kaggle's default 2.10.0+cu128 build omitted `sm_60`. The prior matrix test does not validate detection's compiled NMS/ROIAlign/backward kernels, so the real detector smoke step remains required. Sources: [runtime record](p100_verification.json), [GPU contract](../GPU.md). Current online documentation is conceptual guidance; verify APIs against the pinned installed release.

Proposed initial recipe to freeze after the smoke test: SGD momentum 0.9, weight decay 1e-4, effective batch four, learning rate 0.0025, one-epoch warmup and cosine decay over 24 epochs. This is a starting hypothesis, not a measured optimal setting. Sample one annotation set per image per epoch with a reproducible seed. Use flip/right-angle rotation and modest train-only intensity perturbations; no initial mosaic. Save epochs 8/16/24 and choose using the existing calibration JPEG list and full pipeline PQ; report the other 82 validation JPEGs separately, acknowledging historical reuse. Profile one epoch before quoting total runtime. If the resource budget cannot fit the planned run, freeze a revised schedule before examining validation performance.

Preserve candidate masks before thresholding. Report proposal box recall by area and elongation on development validation, then report **coarse-mask full-frame PQ**. Use a bounded threshold grid and native-coordinate reconstruction with non-overlap resolution required by [EVAL.md](../EVAL.md). AP is secondary; crop Dice is not the competition objective.

## Stage B: conditioned refiner

Compact U-Net decoder with ImageNet-pretrained ResNet18 encoder; 512×512 aspect-preserving crops taken from original 2,048×2,048 pixels. Inputs: three repeated grayscale channels plus two prompt channels (box raster and coarse-mask probability). Initialize extra encoder input weights to zero so image pretraining remains intact. Context margin starts at 25% of box dimensions. A dedicated long-object pathway uses overlapping native crops with the same object prompt and stitches probabilities before instance extraction; do not force an entire elongated filament into a heavily downsampled square. Save geometry inverses and test reconstruction on synthetic non-square edge crops.

Train initially with jittered train-only GT boxes and degraded instance masks, with the selected object's mask as target. Neighbor masks remain background for that prompt. Include empty targets from background proposals. BCE plus soft Dice is the initial segmentation objective; add topology losses only as a separate measured ablation. A quality head predicting matched-mask IoU can be evaluated after segmentation works; it must learn from training-side imperfect proposals rather than validation labels.

To address prompt mismatch without contaminating validation: create a fixed, date-blocked inner prompt-holdout from the 495 training JPEGs; train an auxiliary proposal model on its complement and cache predictions for that inner holdout. Match predictions to each selected annotation record, including false proposals as empty targets, and fine-tune the refiner on this realistic prompt set mixed with jittered GT training crops. This auxiliary model is an explicitly budgeted second step, not a five-fold ensemble. Using same-image fitted detector predictions as if they were OOF is prohibited. Validation detector prompts come only from models trained on the original 495.

At inference reconstruct each prompted instance at native resolution, preserve soft probabilities, resolve duplicate masks by mask IoU and confidence, then assign overlaps deterministically. Avoid box-IoU-only suppression for nearby elongated filaments. Test adjacent filaments, border crops, empty predictions, inverse transforms, and RLE decoding; inspect large-object fragmentation as well as tiny-mask rejection.

## Decision gates

Record four rows on identical validation membership: precision-v2 control; detector coarse masks; detector plus refiner; optional refined proposals plus native-model recovery. Each row includes global PQ/RQ/SQ, additive per-JPEG statistics, paired JPEG bootstrap delta/interval, TP/FP/FN by size, long-object diagnostics, time, and memory. Native dense recovery is admitted only if its marginal PQ improves: do not blindly union candidates from a historically FP-heavy branch.

Proceed to full-training/submission of the new architecture only after a reproducible full-frame gain with understood error changes; a point gain around +0.01 with an interval straddling zero warrants another seed or a blocked assessment before an expensive ensemble. A target of +0.02 validation PQ is a practical experiment goal, not a promised public gain. Freeze the selected recipe, then repeat on the time-blocked/purged outer design described in [the audit](generalization_gap_analysis.md). All detector/refiner/recovery components must obey that outer exclusion. No leaderboard threshold sweeps or unrecorded changes after selection.
